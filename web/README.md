# Centinela site

Landing page of Centinela and of its design system, Vigía: https://centinela.alinedlabs.co (English at `/`, Spanish at `/es/`).

- Static site made with [Astro](https://astro.build), with no UI framework: only our own HTML, CSS and JavaScript run in the browser.
- The design and the first code were generated by Lovable from a prompt by the team; here they became Astro components.
- The review room demo runs in the browser (`src/scripts/desarmar.js`), and the `/pruebas/` page tests it.
- The security headers are in `public/_headers`: a CSP with no inline scripts or styles, and `no-transform` so that Cloudflare does not modify the pages. Nothing in the site may need an inline `<script>`, a `<style>` element or a `style=""` attribute.

## Two languages, one set of components

English is the default and lives at the root; Spanish lives under `/es/`. Both are built from the same components, with two dictionaries.

| Page | English | Spanish |
|---|---|---|
| Landing page | `/` | `/es/` |
| Design system | `/sistema/` | `/es/sistema/` |
| Review room tests (noindex) | `/pruebas/` | `/es/pruebas/` |
| Page not found | `/404.html`, one page in both languages | |

- **Routes.** `astro.config.mjs` sets `i18n` (`defaultLocale: 'en'`, `prefixDefaultLocale: false`). The pages are `src/pages/[...lang]/{index,sistema,pruebas}.astro`; each one calls `localePaths()` (`src/i18n/urls.js`) in `getStaticPaths`, which gives `{ lang: undefined }` for English and `{ lang: 'es' }` for Spanish, and passes `lang` as a prop. `src/pages/404.astro` is a single page that says everything in both languages: Cloudflare serves it for any missing URL, in either language, and Astro only treats `/404` as special.
- **Texts.** `src/i18n/en.json` and `es.json` have flat dotted keys (`hero.title`) and the same keys in both languages. `src/i18n/index.js` has `t(lang, key, fields?)` and `LANGS`; a missing key throws, so a text nobody wrote fails the build. Every component takes a `lang` prop and writes `t(lang, key)`.
  - Values that contain markup (`<code>`, `<strong>`, `<span class="cn-resaltado">`) are written with `set:html`; the others are escaped like any text. `{field}` placeholders are filled by `t`.
  - The keys that start with `js.` are the texts of `src/scripts/*.js`. They are plain text, and the scripts read them in the language of `<html lang>` (`pageLang()`). `astro.config.mjs` keeps only these keys in the code that is sent to the browser, so the scripts can only ask for `js.` keys.
  - A code snippet (`where.*.code`, `use.*.code`) is a list of lines. Its comments are in the language of the page; the Spanish messages and label names in it stay Spanish, because they are what Centinela reads.
  - The review room's example messages (`EJEMPLOS` in `desarmar.js`) are Spanish in both languages. The English page shows an English gloss under the chosen example (`js.example.*.gloss`).
- **Anchors.** The sections have an id per language (`anchor.*` in the dictionaries): `#problem`, `#how-it-works`, `#room`, `#results`, `#limits`, `#where`, `#use`, `#open`, `#team`, `#home` in English and the original `#problema`, `#como-funciona`, `#sala`... in Spanish. The English page also carries the old Spanish ids as empty aliases (`LegacyAnchor.astro`), so a link shared before the English site still lands on its section. The nav's `aria-current` follows the section whose id equals the link's `href`.
- **Language switch.** A plain link to the same page in the other language (`<a lang="es" hreflang="es" href="/es/">`), in the nav and in the footer. No JavaScript.
- **Search engines.** `Base.astro` writes `<html lang>`, a canonical link, `hreflang` alternates (`en`, `es`, `x-default` = English) and `og:locale` for each page. `public/sitemap.xml` is written by hand and lists the indexable pages with their alternates; `public/robots.txt` points to it. The tests page is `noindex` in both languages.
- **What is not translated yet.** The CSS classes (`cn-*`), the ids that the CSS and the scripts use, the file names (`desarmar.js`, `sistema.astro`) and the URL paths `/sistema/` and `/pruebas/` are still the Spanish ones; a later change renames them. The only rule of the CSS that depends on a section id is `#abierto .cn-rejilla-2`, so on the English page the old id `abierto` sits on a wrapper around that grid.

### Changing a text

1. Add or edit the key in **both** `en.json` and `es.json`. The Spanish text is the original copy; the English one is written for English readers, not translated word for word.
2. Use it in a component with `t(lang, 'the.key')`.
3. Run `uv run pytest tests/test_web_i18n.py` from the repository root: it checks that both files have the same keys and `{placeholders}`, that every key the sources ask for exists, that no key is left unused, that markup only appears where the page writes HTML, and that the Python snippets use the library's current API (names, signatures, what their comments say they print).

## Development

```bash
cd web
pnpm install   # only installs versions at least 7 days old
pnpm dev       # http://localhost:4321 (English) and /es/ (Spanish)
pnpm build     # builds dist/
pnpm test      # node --test: the tests in tests/ (build first: some read dist/)
```

The tests are in `tests/` and use Node's own runner (`node --test tests/` works too):

- `desarmar.test.mjs`: the browser port of the review room against the reference outputs of the Python library (`tests/golden/`), in both languages.
- `live.test.mjs`: the live review's client (notice and error messages from ids).
- `worker.test.mjs`: the Worker's contract, with a stand-in for the Anthropic SDK (no install, no network).
- `build.test.mjs`: the built site. Every page has its `lang` and its `hreflang`; no inline script, `<style>` or `style=""`; every `#anchor` and every link inside the site leads somewhere; the English page keeps the old ids; the sitemap lists real pages.

From the repository root, `uv run pytest tests/test_web_i18n.py tests/test_web_reviewer.py` checks the dictionaries and that `cloudflare/src/reviewer.js` matches the library.

## Publishing on Cloudflare

`cloudflare/` is a minimal project that publishes `dist/` with the `cf` CLI, without an Astro adapter. Cloudflare serves the static pages directly; only the `/api/*` routes go through the Worker (`cloudflare/src/worker.js`). The Worker's name, the domain, the routes and the limits are in `cloudflare/cloudflare.config.ts`.

```bash
cd web && pnpm build
cd cloudflare && pnpm install && pnpm exec cf deploy
```

## Live review with Claude (`POST /api/review`)

The "Review with Claude, live" button of the review room sends the text to `POST /api/review`. The Worker reviews it with Claude Haiku 5.5 and the library's reviewer (`LLMDetector`): same instructions, same schema and the same rule, because the decision is made by code from the model's two answers. If the model refuses or answers badly, the message goes to human review.

- **Two switches, both off.** `LIVE_REVIEW` (`'on'` or `'off'`, in `cloudflare/cloudflare.config.ts`) is the Worker's: while it is `'off'` the endpoint answers `off`. `LIVE_REVIEW_ENABLED` (`src/config.js`, a constant of the build) decides whether the pages show the button and the note about it; while it is `false` neither language shows a button that does nothing. The code that talks to the Worker stays (`src/scripts/live.js`, `sala.js`), so turning the review back on is changing both: set `LIVE_REVIEW` to `'on'`, `LIVE_REVIEW_ENABLED` to `true`, build and publish with `--secrets-file`.
- **Request.** `{"text": string, "lang": "en" | "es"}`. `lang` is optional and is checked; it does not change the review.
- **Answer (200).** `{"decision": "review" | "allow", "ai_instructions": true | false | null, "people_deception": true | false | null, "tricks": ["autoridad", ...], "reason": string, "model": "claude-haiku-5-5", "tokens": {"input": n, "output": n}, "fallback": null | "refusal" | "invalid"}`. The decision is `review` if `ai_instructions` or `people_deception`. A refusal or an invalid answer is `review` with both flags `null` and the name of the fallback (it fails closed). The Worker sends ids and flags, never text for people: the page writes the notice in its language from `js.notice.*` and `js.trick.*`, which have the same texts as the Python catalog (`src/centinela/catalog.py`). `reason` is written by the model in Spanish, and the page shows it as it comes with a caption.
- **Errors.** The HTTP status and `{"error": {"code": ...}}`: `off` (503), `origin` (403), `method` (405), `too_long` (413), `bad_request` (400), `empty` (400), `rate_limited` (429, with `Retry-After`), `busy` (503), `upstream` (502), `not_found` (404). The page maps each code to a message in its language (`js.live.error.*`).
- **Instructions.** `cloudflare/src/reviewer.js` is generated from Python with `uv run python web/cloudflare/generate_reviewer.py`; `tests/test_web_reviewer.py` fails if it drifts. The instructions, the schema and the `<mensaje_cliente id="...">` markers are Spanish on purpose: they are what the measurements were made with, and they do not change with the language of the page.
- **Key.** `ANTHROPIC_API_KEY` is a Cloudflare secret (`secret_text`); it is not in the code and does not reach the browser. It is uploaded with the deploy, from a temporary file that is deleted afterwards:

  ```bash
  umask 077; grep -E '^ANTHROPIC_API_KEY=' ../../.env > /tmp/secret.env
  pnpm exec cf deploy --secrets-file /tmp/secret.env; rm -f /tmp/secret.env
  ```

- **Limits.** Up to 2000 characters per message and 700 tokens of answer. 6 reviews per minute per visitor (`LIMIT_VISITOR`) and 60 per minute in total (`LIMIT_TOTAL`), per Cloudflare location. It only accepts requests whose origin is the site. Each review costs about 0.0002 USD (about 1400 input tokens and 100 output tokens).
- **Privacy.** The text is not stored or logged; it travels to Anthropic's API to be reviewed.
- **Current state: off** since the end of the hackathon (2026-11-16): the Worker has `LIVE_REVIEW = 'off'` and the pages do not offer the review. To turn it back on, see "Two switches".
- **Turning it off** (after a presentation): in `cloudflare.config.ts`, `LIVE_REVIEW: bindings.text('off')`, and `pnpm exec cf deploy`. A page that was built with the button still shows it, and the button tells the visitor that the review is off while the demo in the browser keeps working; rebuild with `LIVE_REVIEW_ENABLED = false` to remove it. To delete the key as well, use `npx wrangler secret delete ANTHROPIC_API_KEY --name centinela-web`.
- **SDK.** The Worker uses the official `@anthropic-ai/sdk` (Apache 2.0 license).
