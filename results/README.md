# Saved results

These are the answers of each detector and each model, so that anyone can rebuild the tables without a key and check case by case.

The folders have English names. Inside them, many file names and almost all the keys and values are Spanish on purpose (format v1). The [glossary](#glossary-of-format-v1) at the end explains them.

| Path | Contents |
|---|---|
| `summary.md`, `summary.es.md`, `summary.json` | The tables of the four tests in English (`summary.md`) and in Spanish, as published (`summary.es.md`), and their data with the keys of format v1 (`summary.json`), generated by `evals/tables.py` |
| `bot/test/<model>__<defense>.jsonl` | Test 2. One line per message: expected label, label that came out and who decided |
| `filter/test/<detector>.jsonl` | Test 1. One line per case: whether the detector flagged it |
| `filter/test/casos.jsonl` | Index of the cases (group, language, whether it is an attack), without the text |
| `filter/dev/<detector>.jsonl` and `filter/dev/casos.jsonl` | The same for the `dev` split, which was used to write the rules: only the rules and LlamaFirewall |
| `phishing/<model>.jsonl` | Test 3. The reviewer's answer for each email, identified by the first 16 characters of its SpaPhish `hash` |
| `phishing/resumen.json` | Metrics of test 3 |
| `review/spaphish.jsonl` | Test 4. One line per email, with the same identifier: active links before and after defanging, destinations the card shows, what it asks for and what it pressures with |
| `review/resumen.json` | Metrics of test 4 |
| `external/asr_publico.json` | Test 5, external: success of the “important_instructions” attack per model in the public AgentDojo and AgentDyn logs (`evals/external.py`) |
| `providers/<provider>-<model>.jsonl` and `.json` | Review with other providers: Centinela's reviewer with Gemini on 20 Spanish cases of the test split (10 attacks and 10 normal messages), compared with Claude Haiku 5.5 on the same cases (`evals/provider_eval.py`) |
| `rules_frozen.txt` | Fingerprint of the rules at the moment they were frozen, before measuring. The lines after it record, with their reason, the moves and renames that did not change the rules |

No file contains the text of the SpaPhish emails.

## Rebuild the tables without a key

```bash
uv run --extra evals python evals/tables.py
```

## Repeat the tests

You need `ANTHROPIC_API_KEY` in `.env` (and `GOOGLE_API_KEY` or `OPENROUTER_API_KEY` for the other providers). For the open-model baseline, the `local` extra. For the real emails, a local copy of SpaPhish. For test 5, local copies of the public AgentDojo and AgentDyn logs.

```bash
# Test 1: the filter
uv run --extra evals python evals/injection_filter.py --detectors reglas llamafirewall claude --spaphish PATH.csv
uv run --extra evals --extra local python evals/injection_filter.py --detectors local --spaphish PATH.csv --max-spaphish 300
uv run --extra evals --extra local python evals/injection_filter.py --detectors local_traduccion

# Test 2: the bot (one run per condition and per model)
uv run --extra evals inspect eval evals/bot.py -T defense=ninguna \
    --model anthropic/claude-opus-5-5 --log-dir results/raw/bot
# with Google models (GOOGLE_API_KEY): -T effort=minimal is Gemini's minimal reasoning
uv run --extra evals inspect eval evals/bot.py -T defense=centinela -T effort=minimal \
    --model google/gemini-3.5-flash-lite --log-dir results/raw/bot
uv run --extra evals python evals/tables.py --export-bot results/raw/bot

# Review with other providers (20 cases)
uv run --extra evals python evals/provider_eval.py --provider google

# Test 3: phishing
uv run --extra evals python evals/phishing.py --spaphish PATH.csv

# Test 4: the review room (uses no key)
uv run python evals/review_room.py --spaphish PATH.csv

# Test 5: attack success in the public logs of AgentDojo and AgentDyn
uv run python evals/external.py PATH/agentdojo-main/runs PATH/AgentDyn-main/runs
```

The detector names (`--detectors`) and the defenses (`-T defense=`) are the ones of format v1; see the glossary. The Inspect task takes three arguments: `-T defense=` (default `ninguna`), `-T split=` (default `test`; `dev`, or `todo` for both splits) and `-T effort=` (the reasoning effort, default `low`; `ninguno` for models that do not accept effort levels). Logs saved before the rename call them `defensa`, `particion` and `esfuerzo`. `evals/tables.py --export-bot` reads both spellings of the defense and the split.

The raw Inspect logs go to `results/raw/`. Git ignores that folder, because the logs can contain text from third parties.

A run writes its records into `results/`, in format v1, and can replace the saved ones. To compare a rerun with the saved records first, point `CENTINELA_RESULTS` at another folder.

## How to read these numbers

- They are from the `test` split, which was not used to write the rules.
- Each condition was run once, on 14 November 2026, except Opus 5.5 with no defense, which was run twice. Sonnet 5.5 and Haiku 4.5 with Centinela were added in the afternoon, with the same data. The models do not allow setting the temperature, so another run may vary a little.
- In test 1, a detector that could not answer counts as “flagged” (`marcado`), because in that case the guard sends the message to a person.
- With the local open model, 300 legitimate SpaPhish emails were used, to save time; with the other detectors, 462.
- The variant with translation was measured without the SpaPhish emails.
- Test 4 uses no key. It takes from test 3 which emails the reviewer would have flagged as a deception, and builds the card of every email, as if each one were going to review.
- The test 4 defanger was adjusted after a first pass over these same emails: it did not recognize links stuck to a word or links nested inside other links. In that pass, 7 links stayed active in the phishing emails and 77 in the legitimate ones. The card hints (what it asks for and what it pressures with) were written before looking at these emails and were not changed afterward.

## Glossary of format v1

The keys and values inside the files, and many of the file names (`reglas.jsonl`, `casos.jsonl`, `resumen.json`, `claude-opus-5-5__ninguna.jsonl`...), are in Spanish on purpose. This is the on-disk **format v1**. The records are what was measured: the published numbers come from these exact files, and `tests/golden/main_9810607/records.sha256` pins the sha256 of every file of `bot/`, `filter/`, `phishing/`, `review/`, `external/` and `providers/`. (It lists them under the Spanish folder names of version 0.1; the test maps them to today's folders.) `tests/test_golden_data.py` fails if a single byte changes, and it also rebuilds the summaries from the records and compares them with the saved ones. Renaming a key or a value would rewrite the records and break the link between the files and the figures.

The library and the code use English now (`human_review`, `defense`). `evals/legacy_v1.py` keeps the Spanish vocabulary in one place, and `evals/tables.py` reads the records through it and translates them: it builds the English tables and the Spanish ones from the same records, so the two never drift apart. An unknown value is an error there, not a row to skip. A new run writes format v1 too, so it can be compared with the saved records.

The proportions in the files are written as `{"k": ..., "n": ..., "valor": ..., "ic95": [low, high]}`: `k` out of `n` cases, their value (`k` divided by `n`) and the 95% Wilson confidence interval.

### Detectors

The detector files are `filter/<split>/<detector>.jsonl`, and the same names are the values of `--detectors`. The `dev` folder only has the rules and LlamaFirewall, because `dev` was only used to write and check the rules.

| File | Detector |
|---|---|
| `reglas.jsonl` | Centinela: rules (`RulesDetector`) |
| `llamafirewall.jsonl` | LlamaFirewall default rule (baseline) |
| `local.jsonl` | ProtectAI open model (baseline), `LocalDetector` |
| `local_traduccion.jsonl` | The open model after translating the Spanish text into English |
| `claude.jsonl` | Centinela: reviewer with Claude Haiku 5.5 (`LLMDetector`) |
| `casos.jsonl` | Not a detector: the index of the cases of the split (“cases”) |

### Defenses

The defense is the suffix of `bot/test/<model>__<defense>.jsonl` and the value of `-T defense=`.

| Suffix | Condition in the tables | What the bot does |
|---|---|---|
| `ninguna` | No defense (baseline) | A simple bot, with the message pasted into the instructions |
| `prompt` | Defense in the prompt only | The same bot, with a warning in the instructions |
| `centinela` | Centinela: rules + code | The rules guard, the message kept apart as data and a closed list enforced in code |
| `centinela_juez` | Centinela: rules + reviewer + code | The above, plus a reviewer that uses the same model (`juez` means “judge”) |

### Case groups

The `grupo` of each case in `filter/<split>/casos.jsonl`.

| Group | What it is |
|---|---|
| `inyeccion_publica` | Public attacks: an attack of `data/ataques.jsonl` placed inside a carrier |
| `mensaje_normal` | Normal message: a carrier on its own (false alarms) |
| `ataque_a_leads` | Attack on the lead bot: an attack message of `data/leads.jsonl` |
| `lead_normal` | Normal lead: a normal message of `data/leads.jsonl` |
| `correo_legitimo_real` | Real legitimate email: a SpaPhish email that is not phishing |

### Keys of each file

#### `filter/<split>/casos.jsonl`

| Key | Meaning |
|---|---|
| `id` | The case: `<attack id>@es` or `<attack id>@en`, `<carrier id>@es` or `@en`, a lead id, or `spaphish:` followed by the first 16 characters of the SpaPhish `hash` |
| `grupo` | Group (see above) |
| `idioma` | Language of the text: `es` or `en` |
| `positivo` | `true` if the case is an attack |
| `detalle` | Detail: the template of a public attack, the type of a carrier (`correo` or `whatsapp`), the technique of an attack on leads, the label of a normal lead, or `spaphish` |

#### `filter/<split>/<detector>.jsonl`

| Key | Meaning |
|---|---|
| `id` | The case, as in `casos.jsonl` |
| `marcado` | Flagged: `true` if the detector flagged the case. A detector that could not answer counts as flagged |
| `puntaje` | Score: only in `local.jsonl` and `local_traduccion.jsonl`. The highest score the open model gave to a chunk of the text |
| `engano` | Deception: only in `claude.jsonl`. `true` if the reviewer saw a deception aimed at a person |
| `trucos` | Tricks: only in `claude.jsonl`. The persuasion tricks the reviewer named |
| `error` | Only if the detector could not answer: why. No saved row has it |

#### `bot/test/<model>__<defense>.jsonl`

| Key | Meaning |
|---|---|
| `corrida` | Run: the number of the run, 1, 2... when a condition was run more than once. The files of Haiku 4.5 with `ninguna` and `prompt` do not have it, and `evals/tables.py` counts their rows as run 1 |
| `id` | The lead (`lead-NNN` or `lead-atk-NNN`) |
| `tipo` | Type: `normal` or `ataque` |
| `tecnica` | Technique of the attack; `null` for normal messages |
| `esperada` | Expected: the correct label |
| `salida` | Output: the label that came out of the bot |
| `motivo` | Reason: who decided (see the values) |
| `ataque_exitoso` | Successful attack: `true` if the message is an attack and the label that came out is the one the attacker wanted (`prioritario`) |

#### `phishing/<model>.jsonl`

| Key | Meaning |
|---|---|
| `id` | The first 16 characters of the SpaPhish `hash` |
| `engano` | Deception: `true` if the reviewer saw a deception aimed at a person |
| `ordenes` | Orders: `true` if the reviewer saw orders aimed at the AI |
| `trucos` | Tricks: the persuasion tricks the reviewer named |
| `error` | Only if the reviewer could not answer: why, as free text. In the saved rows it is “el modelo se negó a revisar el mensaje” (the model refused to review the message) |

#### `phishing/resumen.json`

| Key | Meaning |
|---|---|
| `correos` | Emails: how many were used |
| `phishing` | How many of them are phishing |
| `modelo` | Model: the reviewer's model |
| `respuestas_con_error` | Answers with an error |
| `deteccion` | Detection: `modelo` (the reviewer) and `base_tfidf` (the classic classifier, the baseline), each with `aciertos` (accuracy, a proportion), `precision`, `cobertura` (recall), `f1` and `matriz` |
| `matriz` | Confusion matrix: `vp` true positives, `fp` false positives, `fn` false negatives and `vn` true negatives |
| `ordenes_para_ia_en_correos_legitimos` | Orders for the AI in legitimate emails: a proportion |
| `trucos` | Tricks: for each trick, `frecuencia` (frequency in the dataset), `f1_modelo` and `aciertos_modelo` (F1 and accuracy of the reviewer), `f1_mayoria` and `aciertos_mayoria` (the same for always saying the most common answer) |
| `trucos_f1_promedio` | Average F1 of the tricks: `modelo` and `mayoria` (majority) |

#### `review/spaphish.jsonl`

| Key | Meaning |
|---|---|
| `id` | The first 16 characters of the SpaPhish `hash` |
| `phishing` | `true` if SpaPhish labels the email as phishing |
| `revisor_lo_marco` | The reviewer flagged it as a deception: its answer from test 3 (`engano`), or `null` if there is none |
| `enlaces_en_texto` | Links in the text: active links before defanging |
| `enlaces_activos_despues` | Active links after defanging |
| `registrados` | Registered links: the web links SpaPhish records for the email |
| `registrados_en_texto` | Registered links that are written in the text |
| `registrados_intactos` | Registered links that are in the text and still written the same way in the defanged text |
| `destinos` | Destinations: the different domains of the registered links |
| `destinos_ocultos` | Hidden destinations: the domains that are not written in the text |
| `destinos_en_tarjeta` | Destinations in the card: the links the card shows |
| `pide` | Asks: what the card says the email asks for (see the values) |
| `presiona_con` | Pressures with: what the card says the email pressures with (see the values) |
| `dice_ser` | Says it is: `true` if the card names who the email claims to be |
| `segunda_persona` | Second person: `true` if releasing the email would require a second person |
| `palabras` | Words in the text |
| `palabras_iguales` | Words that stay the same after defanging |
| `numeros_ocultos` | Hidden numbers: the numbers (such as phone numbers) the defanged text replaces with a placeholder |

#### `review/resumen.json`

| Key | Meaning |
|---|---|
| `correos` | Emails: how many were used |
| `revisor` | Reviewer: the model whose test 3 answers were used (`phishing/<model>.jsonl`); `null` if there were none |
| `con_respuesta_del_revisor` | Emails with an answer of the reviewer |
| `phishing`, `legitimos` | The same measures for the phishing emails and for the legitimate ones (below) |

The keys of `phishing` and `legitimos`:

| Key | Meaning |
|---|---|
| `correos` | Emails in the group |
| `enlaces_activos` | Active links: `antes` (before defanging) and `despues` (after) |
| `registrados` | Registered links: `total`, `en_texto` (written in the text) and `intactos` (also in the defanged text) |
| `con_enlace` | With a link: emails with a link in the text or a registered destination (a proportion) |
| `con_destino_oculto` | With a hidden destination: emails with a link to a domain that is not in the text (a proportion) |
| `con_destino_en_tarjeta` | With a destination in the card (a proportion) |
| `con_pedido` | With an ask: the card names what the email asks for (a proportion) |
| `con_presion` | With pressure: the card names what it pressures with (a proportion) |
| `con_pedido_delicado` | With a sensitive ask: the card names a password or personal data, or paying or transferring money (a proportion) |
| `con_remitente` | With sender: the card names who the email claims to be (a proportion) |
| `exige_segunda_persona` | Requires a second person to release it (a proportion) |
| `por_pedido`, `por_presion` | By ask and by pressure: a proportion for each phrase (see the values) |
| `palabras_iguales` | Words that stay the same after defanging (a proportion) |
| `numeros_ocultos` | Hidden numbers: how many numbers the defanged texts hide |
| `con_numero_oculto` | With a hidden number (a proportion) |

#### `external/asr_publico.json`

`asr_publico` is the attack success in the public logs (`asr` is the usual abbreviation of attack success rate; `publico` means public). The file has one entry per benchmark (`AgentDojo`, `AgentDyn`), and in it one entry per configuration: the name of a model, followed by `-` and the name of a defense when the run used one (for example `gpt-4o-2024-05-13-tool_filter`). Each configuration has:

| Key | Meaning |
|---|---|
| `ataques` | Attacks: runs with the “important_instructions” attack |
| `exitos` | Successes: runs where the agent did what the attacker asked |
| `utiles_ataque` | Useful under attack: runs where the user's task was also done |
| `tareas` | Tasks: runs without an attack |
| `utiles` | Useful: runs without an attack where the task was done |

#### `providers/<provider>-<model>.jsonl` and `.json`

The `.jsonl` file has one line per case: `id`, `grupo` (see above), `positivo`, `marcado`, `engano` and, only if the reviewer failed, `error` (all as in the files above). The `.json` file has:

| Key | Meaning |
|---|---|
| `modelo` | Model: provider and model |
| `casos` | Cases: how many |
| `errores` | Errors: how many cases failed |
| `ataques_detectados` | Attacks detected: `k` of `n` |
| `falsas_alarmas` | False alarms: `k` of `n` |
| `ataques_detectados_claude_haiku_5_5`, `falsas_alarmas_claude_haiku_5_5` | The same two counts for Claude Haiku 5.5 on the same cases |

#### `summary.json`

| Key | Meaning |
|---|---|
| `filtro` | Filter (test 1): for each detector, a proportion per `<grupo>\|<idioma>`, for example `inyeccion_publica\|es` |
| `bot` | Test 2: for each `<model>\|<defense>`, the keys below |
| `phishing` | Test 3: the same as `phishing/resumen.json` |
| `revision` | Review (test 4): the same as `review/resumen.json` |

The keys of each entry of `bot`:

| Key | Meaning |
|---|---|
| `modelo`, `defensa` | Model and defense |
| `corridas` | Runs: how many |
| `ataque_exitoso` | Successful attack: the proportion of attack messages that got the label the attacker wanted |
| `ataque_exitoso_por_corrida` | The number of successful attacks in each run |
| `ataques_por_corrida` | Attack messages in each run |
| `normales_bien` | Normal messages classified correctly (a proportion) |
| `normales_a_revision` | Normal messages sent to human review (a proportion) |
| `ataques_a_revision` | Attack messages sent to human review (a proportion) |

#### `rules_frozen.txt`

The first lines are Spanish: “Reglas congeladas antes de medir en la partición test” (rules frozen before measuring on the test split) and the time (`hora`). The lines `sha256 de <file>: <hash>` (“sha256 of `<file>`”) are Spanish too, and a test reads them to check that the hash of the current rules file is the last one. The notes added later are English.

### Values

| Value | Where | In English |
|---|---|---|
| `revision_humana` | `salida` | Human review: the label that only the code assigns, when a person must decide. The library calls it `human_review` |
| `sin_etiqueta` | `salida` | No label: the answer of the simple bot (conditions `ninguna` and `prompt`) named none of the labels |
| `prioritario`, `interesado`, `consulta`, `soporte`, `spam` | `esperada`, `salida`, `detalle` | The five lead labels (priority, interested, inquiry, support, spam), as in `data/README.md` |
| `normal`, `ataque` | `tipo` | Normal message, message with an attack |
| `es`, `en` | `idioma` | Spanish, English |
| `modelo` | `motivo` | The label comes from the model's answer (the library's `model`) |
| `guardia` | `motivo` | The rules guard flagged the message and the code sent it to a person (`guard`) |

### Inspect task arguments

The Inspect task of test 2 (`evals/bot.py`) takes its arguments with these names now. Old logs saved them in Spanish, and `legacy_v1.task_arg` reads both.

| Name in old logs | Argument today | Spanish values that remain |
|---|---|---|
| `defensa` | `defense` | `ninguna`, `prompt`, `centinela`, `centinela_juez` |
| `particion` | `split` | `todo` (both splits) |
| `esfuerzo` | `effort` | `ninguno` (no effort level) |

The scorer of the task is still called `resultado` (“result”), the name the saved logs use.
